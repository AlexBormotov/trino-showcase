# Metric catalog

The source of truth is [`semantic/clinic_analytics.yaml`](../semantic/clinic_analytics.yaml) (Apache Ossie). This page explains the definitions; if it disagrees with the YAML, the YAML wins. MetricFlow definitions are generated by `uv run poe semantic`. How the pipeline works and why: [ADR 0003](adr/0003-ossie-as-metric-source.md).

Each value is checked against an independent expectation in `tests/integration/test_metrics.py`.

| Metric | Definition | Ossie expression | Dataset, default time | Checked against |
|---|---|---|---|---|
| `encounter_count` | Number of encounters | `COUNT(encounter.*)` | encounter, `start_ts` | Seed manifest (clean source) |
| `active_patients` | Distinct patients with at least one encounter in the period | `COUNT(DISTINCT encounter.patient_hk)` | encounter, `start_ts` | SQL over the canonical model |
| `avg_length_of_stay_days` | Average inpatient length of stay, in days | `(SUM(encounter.length_of_stay_days)) / (SUM(encounter.inpatient_stay))` | encounter, `start_ts` | SQL over the canonical model |
| `readmission_rate_30d` | Share of inpatient stays followed by another inpatient admission within 30 days of discharge | `(SUM(encounter.readmitted_30d)) / (SUM(encounter.inpatient_stay))` | encounter, `start_ts` | SQL over the canonical model (EXISTS) |
| `claim_denial_rate` | Denied claims over adjudicated (paid or denied) claims | `(SUM(claim.denied_claim)) / (SUM(claim.adjudicated_claim))` | claim, `service_dt` | Seed manifest |

Group-by dimensions: `<dataset>__<field>` (for example `encounter__tenant_id`, `claim__claim_status`), `patient__gender` and `patient__city` through the relationships, and `metric_time__day|week|month|quarter|year`.

```bash
PYTHONIOENCODING=utf-8 uv run mf query --metrics encounter_count,readmission_rate_30d --group-by encounter__tenant_id
PYTHONIOENCODING=utf-8 uv run mf query --metrics claim_denial_rate --group-by patient__gender
```

## Definitions and caveats

- **Row-level flags live in dbt, aggregation lives in Ossie.** `inpatient_stay`, `length_of_stay_days` and `readmitted_30d` are columns of `marts.fct_encounter`; `denied_claim` and `adjudicated_claim` are columns of `marts.fct_claim`. Ossie expressions are aggregates over row-level fields, and the readmission rule needs a join across rows.
- **Readmission** uses the first inpatient admission that *starts after* discharge, not the next stay by start time. 151 of 1,805 inpatient stays overlap another stay of the same patient, and `lead()` over start time missed readmissions that followed them. A dbt test cross-checks the flag with a differently written query.
- **Readmission and length of stay are per tenant.** A patient is identified within one tenant (`patient_hk` includes `tenant_id`). Cross-tenant readmissions are invisible by design: tenants are separate clients.
- **Claims include medication claims.** Synthea bills medications as separate claims on the same encounter, so there are about 1.8 claims per encounter. Denial rate is per claim, not per encounter.
- **Pending claims** (the last 14 days of the window) are not adjudicated yet and are left out of the denial rate denominator.
- **Denials are injected.** Synthea closes every claim; the seeder marks about 8% denied (`docs/PLAN.md`).
- **The clinic_c archive is missing three months.** Encounter-based metrics for clinic_c have gaps in 2022-03, 2023-08 and 2025-01. Claims of the lost encounters still count toward the denial rate, because the claims themselves were kept.
- **Round trip.** Ossie → MetricFlow → Ossie keeps every expression except `encounter_count`, which comes back as `SUM(1)` without its dataset. The converter reports this as `CONSTANT_METRIC_SEMANTIC_MODEL_LOSS`. Ratio metrics come back together with their generated `__numerator` and `__denominator` metrics.
